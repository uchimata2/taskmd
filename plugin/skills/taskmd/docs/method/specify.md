# specify

> Phase 1 of 4. Spine — including this phase's **exit criterion**:
> [`../METHOD.md`](../METHOD.md) §2.

Specify answers one question: **what has to be true at the end for this to have worked?** It does
not decide how, and it does not begin.

## Procedure

1. **State the outcome.** One paragraph, describing what exists at the end that does not exist now.
   Write it as a result, not as an activity: "the three candidate suppliers are compared on the four
   criteria the board asked about" — not "look into suppliers".

2. **Draw the boundary.** Say what is in and, more usefully, what is out. The out-list is what stops
   the work expanding while nobody is watching, so it is worth more thought than the in-list. Where
   something is excluded because it belongs to another task, name that task.

3. **Name the inputs.** What must be read, gathered or obtained before the work can start. An input
   nobody can reach is a dependency in disguise — record it as one and say so.

4. **Write the acceptance criteria.** Each one states a fact that will be either true or false when
   the work is done, and says what would show it. If you cannot describe what a failure would look
   like, it is an aspiration, not a criterion — sharpen it or drop it.

5. **Record what is still open.** Anything genuinely undecided, with who decides it. A question that
   only blocks a later phase stays open and is noted; a question that changes the outcome itself
   must be answered before this phase can end.

6. **Ask, once.** Take everything you still need to reach the exit criterion and put it in a single
   turn ([`../METHOD.md`](../METHOD.md) §3.2). Then stop and wait — specify is agreed by the owner,
   not declared by the person writing it.

## What "enough detail" means here

Enough to judge the result, and no more. The temptation is to specify how the work will be done,
which pre-empts `plan` while the ground is least understood. If a sentence would still be true had
someone chosen a completely different approach, it belongs here. If not, it is a plan step.

## Worked example — a research task

> **Outcome.** A written answer to whether the current onboarding material reduces support
> contacts in a new customer's first month, with the evidence it rests on.
>
> **In.** The last four quarters of contact volumes; the two onboarding revisions in that window.
> **Out.** Recommending a replacement — that is a separate task if the answer turns out to be no.
>
> **Criteria.**
> - The answer names a direction (reduces / does not / cannot be determined) and does not hedge.
> - Every figure quoted can be traced to a named source, so a reader can check one at random.
> - Where the evidence cannot settle the question, that is stated as a finding rather than filled
>   with judgement.
> - Someone who was not involved can read it and say what would change the conclusion.

Note what is absent: no method, no tools, no sections. Those are `plan`'s. Note also the third
criterion — it makes "we could not tell" a legitimate, passing outcome, which is what stops the
research from being quietly steered toward a usable answer.

## Leaving this phase

Nothing else has started — not the plan, not a first draft, not "just the easy part". →
[`plan`](plan.md), **when it is asked for** ([`../METHOD.md`](../METHOD.md) §3.1).
